# מה נשאר לפני פרסום של photag

נכתב ב‑2026‑10‑01. הרשימה מסודרת לפי חשיבות; החלק הראשון (רישוי) הוא החסם האמיתי, השאר שיפורים ובדיקות.
סימון: **[חסם]** = לא לפרסם בלי זה · **[מומלץ מאוד]** · **[נחמד]**.

## 1. רישוי וצד משפטי

- **[חסם] אין קובץ LICENSE במאגר.** בלי רישיון, הקוד שלכם "כל הזכויות שמורות" כברירת מחדל. צריך לבחור (MIT / GPL-3.0 / אחר) — והבחירה תלויה בשני הסעיפים הבאים.
- **[חסם] משקולות זיהוי הפנים (InsightFace `buffalo_l`) מורשות לשימוש לא‑מסחרי / מחקר בלבד.** האפליקציה מורידה אותן בזמן ריצה (לא מצורפות), אבל פרסום אפליקציה שמשתמשת בהן מחייב לציין את זה, ולא מתאים לשימוש מסחרי. אם רוצים מסחרי — צריך מודל זיהוי אחר או רישיון. כדאי לאמת את הרישיון העדכני לפני פרסום.
- **[חסם] ffmpeg שמגיע עם `imageio-ffmpeg` הוא build ברישיון GPL** (כולל x264). אם הוא נארז בתוך ה‑EXE/המתקין (כך `photag.spec` עושה עכשיו), הפצת התוכנה מחייבת עמידה ב‑GPL: צירוף נוסח הרישיון והצעת קוד המקור של ffmpeg, ותאימות הרישיון של photag. חלופות: רישיון GPL‑3.0 ל‑photag; או build של ffmpeg בלי רכיבי GPL; או הורדה בזמן ריצה (כמו המודלים) במקום אריזה.
- **[מומלץ מאוד] קובץ הודעות צד שלישי** (`THIRD_PARTY_NOTICES`): FastAPI, uvicorn, pywebview, Pillow, NumPy, SciPy, ONNX Runtime, InsightFace, ffmpeg, וגם הגופנים Heebo ו‑Frank Ruhl Libre (SIL OFL — צריך לצרף את נוסח הרישיון).
- **[מומלץ מאוד] שם ומיתוג:** האפליקציה משתמשת בשם "Lightroom Classic" רק בהקשר תיאורי (ייבוא `.lrcat`, "בהשראת"). לא להשתמש בלוגו/בשם של Adobe ולא לרמוז על שיוך. השם photag עצמו נקי.
- **[מומלץ מאוד] פרטיות:** לתעד ב‑README שתיוג AI שולח תמונות ממוזערות לספק שהמשתמש בחר (ורק כשהוא מפעיל), ושכל השאר מקומי. HandBrake אינו מצורף (GPL) — המשתמש מתקין בנפרד, וזה בסדר.

## 2. בנייה והפצה

- **[חסם] לבנות את ה‑EXE ולבדוק על מחשב נקי** (מכונה וירטואלית): `build.bat` לא הורץ מאז שנוספו `imageio-ffmpeg`, התיקונים ב‑`photag.spec` ו‑`installer.iss`. לוודא: האפליקציה עולה, ffmpeg נמצא בתוך החבילה, זיהוי פנים עובד, הדחיסה עובדת עם HandBrakeCLI מותקן, ושהמתקין מותקן/מוסר נקי.
- **[חסם] בדיקת עדכון אמיתית מקצה לקצה.** נבדק רק מול GitHub מדומה, במצב שלא מפעיל את המתקין. לבדוק פעם אחת באמת: להתקין 1.0.0, לפרסם 1.0.1, ולראות את החלון, ההורדה, ההתקנה השקטה (`/SILENT /update=1`) והפעלה מחדש.
- **[מומלץ מאוד] חתימת קוד (Authenticode).** בלי חתימה: SmartScreen יזהיר בהתקנה ראשונה וגם בעדכון, ומנועי אנטי‑וירוס עלולים לסמן EXE שנוצר ב‑PyInstaller. בנוסף, העדכון האוטומטי מריץ מתקין לא חתום; האימות היחיד הוא ה‑SHA‑256 שמגיע מ‑GitHub.
- **[חסם] תהליך שחרור ב‑GitHub** (`giamat13/photag`):
  - המאגר חייב להיות **ציבורי** — בדיקת העדכון קוראת את ה‑API בלי הרשאות, ומאגר פרטי מחזיר 404 (העדכון פשוט לא יעבוד, בשקט).
  - תג `vX.Y.Z` שזהה ל‑`app/version.py`; לצרף קובץ בשם `photagSetup.exe` (בדיוק; הוא נבחר לפי התבנית `photagSetup*.exe`).
  - GitHub מצרף ל‑asset חתימת SHA‑256 (digest) אוטומטית — בלעדיה העדכון האוטומטי לא יתקין, וישלח לדף השחרור.
  - **גוף ה‑Release הוא מה שמוצג בחלון "מה חדש"**: לכתוב אותו בשביל משתמשים (כותרות, נקודות, **הדגשה**, `קוד` נתמכים).
  - אחרי כל שחרור: להעלות את `app/version.py`, ולפני כן לבנות עם `build.bat`.
- **[מומלץ מאוד] להעביר את הבדיקות מהספרייה הזמנית למאגר.** כל הבדיקות שרצו (דחיסה מול HandBrake אמיתי, עדכון מול GitHub מדומה, תיוג AI מול ספקים מדומים, ממשק ב‑Playwright) נמצאות בתיקיית הסשן ולא במאגר. כדאי ליצור `tests/` והרצה אוטומטית (GitHub Actions).
- **[נחמד] הצמדת גרסאות ב‑`requirements.txt`** (כרגע בלי גרסאות) כדי שבנייה תהיה ניתנת לשחזור.

## 3. אבטחה וחוסן

- **[מומלץ מאוד] שרת מקומי חשוף לדפדפן.** האפליקציה מריצה שרת על `127.0.0.1:8756`. כל אתר שפתוח בדפדפן יכול לנסות לפנות אליו. כיום זה מוגן חלקית (בקשות JSON חוצות‑אתר דורשות CORS), אבל לפני פרסום כדאי: בדיקת כותרות `Host`/`Origin` וטוקן אקראי לכל הפעלה — במיוחד כי יש נקודות קצה שמוחקות, משנות הגדרות ומחזיקות מפתחות API.
- **[מומלץ מאוד] פורט קבוע (8756).** אם הפורט תפוס האפליקציה לא תעלה; לבחור פורט פנוי. וגם: מופע יחיד (הפעלה שנייה לא אמורה להתנגש).
- **[מומלץ מאוד] ניקוי גיבויי וידאו.** כל דחיסה שומרת את הגרסה הישנה ב‑`media/.originals` ואין עדיין מסך לראות/למחוק גיבויים, כך שהם מצטברים. שווה להוסיף "גיבויים" בהגדרות הקטלוג.
- **[מומלץ מאוד] מסד הנתונים:** שינויי סכמה נעשים ב‑`ALTER TABLE` נקודתיים. כדאי מספר גרסת סכמה, וגיבוי אוטומטי של `catalog.db` לפני שדרוג.
- **[נחמד] יומן ושליחת דוח תקלה:** כשהאפליקציה רצה בלי חלון קונסולה השגיאות הולכות ל‑`photag.log` בלבד. כפתור "פתח יומן / דווח על תקלה" יעזור למשתמשים.

## 5. הפערים במוצר (לא חוסמים, אבל משתמשים ישימו לב)

- README באנגלית + צילומי מסך + הוראות התקנה (כיום עברית בלבד).
- עריכה: אין עריכת RAW; עריכת Develop משנה את הקובץ (עם גיבוי של המקור) ולא נשמרת כהגדרות נפרדות כמו ב‑Lightroom.
- הצעות מילות מפתח בפאנל ה‑Keywording לא הציגו תוצאות בניסוי (נדחה לבקשתך; שורש הבעיה לא אובחן).
- אין חיפוש טקסט חופשי לפי תוכן התמונה (התיוג האוטומטי המקומי הוסר; אפשר להחזיר — ראו `docs/project-history.md`).

## 6. סדר פעולות מומלץ

1. לבחור רישיון, ולהחליט מה עושים עם ffmpeg (GPL) ועם מודל הפנים (לא‑מסחרי).
2. `build.bat` על מכונה נקייה; לתקן מה שנשבר.
3. להעביר את הבדיקות ל‑`tests/`.
4. להוסיף בדיקת Host/Origin וגיבויי וידאו.
5. שחרור `v1.0.0` ב‑GitHub, ואז `v1.0.1` כדי לבדוק את העדכון האוטומטי באמת.
6. רק אז לפרסם.
